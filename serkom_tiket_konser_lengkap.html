Aplikasi Pemesanan Tiket Konser Berbasis Web

Panduan lengkap step-by-step membangun aplikasi pemesanan tiket konser dari nol hingga siap uji kompetensi BNSP. Mencakup autentikasi multi-role (Customer & Admin), perancangan relasi 4 tabel basis data, dashboard rekapitulasi pesanan masuk dengan filter periode, master CRUD tiket konser dengan upload gambar poster, CRUD manajemen data pengguna (Admin & Customer), serta alur transaksi booking atomik dengan pencegahan overbooking.

Framework: Laravel 10/11 Database: MySQL (InnoDB) Frontend: Tailwind CSS & Blade Auth: Laravel Breeze
🗺️ Arsitektur Relasi Basis Data (ERD Tiket Konser)
Kardinalitas 1:N & N:M

Struktur 4 tabel yang ternormalisasi (3NF). Hubungan antara Transaksi (orders) dan Tiket Konser (tickets) adalah Many-to-Many yang dihubungkan melalui tabel pivot order_details.

users Master Akun
  • 🔑 id BIGINT (PK)
  • name VARCHAR(255)
  • email VARCHAR(255) [UNIQUE]
  • phone VARCHAR(20)
  • password VARCHAR(255)
  • role ENUM('admin','customer')
orders Header Transaksi
  • 🔑 id BIGINT (PK)
  • 🔗 user_id FK -> users.id
  • order_code VARCHAR [UNIQUE]
  • customer_name VARCHAR(255)
  • customer_phone VARCHAR(20)
  • total_price INT
  • status ENUM('pending','paid','cancelled')
  • order_date DATE
order_details Pivot / Rincian
  • 🔑 id BIGINT (PK)
  • 🔗 order_id FK -> orders.id [CASCADE]
  • 🔗 ticket_id FK -> tickets.id [CASCADE]
  • quantity INT
  • unit_price INT (Harga Historis)
  • subtotal INT
tickets Master Konser
  • 🔑 id BIGINT (PK)
  • concert_name VARCHAR(255)
  • artist VARCHAR(255)
  • venue VARCHAR(255)
  • event_date DATETIME
  • category ENUM('VIP','Festival','Regular')
  • price INT
  • stock INT
  • poster VARCHAR (Path Gambar)

// app/Models/User.php
namespace App\Models;

use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Foundation\Auth\User as Authenticatable;
use Illuminate\Notifications\Notifiable;

class User extends Authenticatable
{
    use HasFactory, Notifiable;

    protected $fillable = [
        'name',
        'email',
        'phone',
        'password',
        'role', // [TAMBAHKAN]
    ];

    protected $hidden = [
        'password',
        'remember_token',
    ];

    protected function casts(): array
    {
        return [
            'email_verified_at' => 'datetime',
            'password' => 'hashed',
        ];
    }

    // [TAMBAHKAN] Helper pengecekan hak akses
    public function isAdmin(): bool
    {
        return $this->role === 'admin';
    }

    public function isCustomer(): bool
    {
        return $this->role === 'customer';
    }

    // [TAMBAHKAN] Relasi One-to-Many ke Transaksi Pemesanan
    public function orders()
    {
        return $this->hasMany(Order::class);
    }
}

1.4 Middleware Proteksi Administrator (IsAdmin)

📄 app/Http/Middleware/IsAdmin.php Middleware
PHP 
<?php
// app/Http/Middleware/IsAdmin.php
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;
use Symfony\Component\HttpFoundation\Response;

class IsAdmin
{
    public function handle(Request $request, Closure $next): Response
    {
        // Cek login & role admin
        if (Auth::check() && Auth::user()->role === 'admin') {
            return $next($request);
        }

        // Jika bukan admin, tolak & kembalikan ke katalog
        return redirect()->route('concerts.index')->with('error', 'Akses ditolak! Halaman ini khusus Administrator.');
    }
}
💡 Pendaftaran Middleware di Laravel 11 (bootstrap/app.php):
Buka bootstrap/app.php, tambahkan alias: $middleware->alias(['admin' => \App\Http\Middleware\IsAdmin::class]);

📋 Praktek 3: CRUD Master Data Tiket Konser (Sisi Admin)
CRUD Lengkap & File Upload

Fitur bagi administrator untuk menambah konser baru, mengunggah banner poster ke disk storage public, mengubah kuota tiket, melihat preview gambar, dan menghapus tiket dengan konfirmasi modal.

3.1 Controller TicketController (Resource 7 Method)

📄 app/Http/Controllers/Admin/TicketController.php Controller
PHP 
<?php
// app/Http/Controllers/Admin/TicketController.php
namespace App\Http\Controllers\Admin;

use App\Http\Controllers\Controller;
use App\Models\Ticket;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Storage;

class TicketController extends Controller
{
    // 1. Tampilkan Semua Tiket Konser
    public function index()
    {
        $tickets = Ticket::latest()->paginate(10);
        return view('admin.tickets.index', compact('tickets'));
    }

    // 2. Form Tambah Tiket
    public function create()
    {
        return view('admin.tickets.create');
    }

    // 3. Simpan Tiket Baru (Create)
    public function store(Request $request)
    {
        $validated = $request->validate([
            'concert_name' => 'required|string|max:255',
            'artist'       => 'required|string|max:255',
            'venue'        => 'required|string|max:255',
            'event_date'   => 'required|date',
            'category'     => 'required|in:VIP,Festival,Regular',
            'price'        => 'required|numeric|min:0',
            'stock'        => 'required|integer|min:1',
            'description'  => 'nullable|string',
            'poster'       => 'nullable|image|mimes:jpeg,png,jpg|max:2048',
        ]);

        // Upload banner poster jika ada
        if ($request->hasFile('poster')) {
            $validated['poster'] = $request->file('poster')->store('posters', 'public');
        }

        Ticket::create($validated);

        return redirect()->route('admin.tickets.index')->with('success', 'Tiket konser berhasil ditambahkan!');
    }

    // 4. Form Edit Tiket
    public function edit(Ticket $ticket)
    {
        return view('admin.tickets.edit', compact('ticket'));
    }

    // 5. Update Tiket (Update)
    public function update(Request $request, Ticket $ticket)
    {
        $validated = $request->validate([
            'concert_name' => 'required|string|max:255',
            'artist'       => 'required|string|max:255',
            'venue'        => 'required|string|max:255',
            'event_date'   => 'required|date',
            'category'     => 'required|in:VIP,Festival,Regular',
            'price'        => 'required|numeric|min:0',
            'stock'        => 'required|integer|min:0',
            'description'  => 'nullable|string',
            'poster'       => 'nullable|image|mimes:jpeg,png,jpg|max:2048',
        ]);

        if ($request->hasFile('poster')) {
            // Hapus file lama jika ada
            if ($ticket->poster && Storage::disk('public')->exists($ticket->poster)) {
                Storage::disk('public')->delete($ticket->poster);
            }
            $validated['poster'] = $request->file('poster')->store('posters', 'public');
        }

        $ticket->update($validated);

        return redirect()->route('admin.tickets.index')->with('success', 'Data tiket konser berhasil diperbarui!');
    }

    // 6. Hapus Tiket (Delete)
    public function destroy(Ticket $ticket)
    {
        if ($ticket->poster && Storage::disk('public')->exists($ticket->poster)) {
            Storage::disk('public')->delete($ticket->poster);
        }

        $ticket->delete();

        return redirect()->route('admin.tickets.index')->with('success', 'Tiket konser berhasil dihapus!');
    }
}

👥 Praktek 4: CRUD Manajemen Data Pengguna (User Management)
CRUD User & Proteksi Akun

Fitur esensial administrator untuk mengelola pengguna (Admin & Customer). Mencakup pencarian user berdasarkan nama/email, filtering peran, penambahan akun baru, pembaruan profil tanpa harus mengganti password, serta proteksi keamanan agar admin tidak dapat menghapus akunnya sendiri yang sedang aktif.

4.1 Controller UserController (Resource CRUD & Proteksi Self-Delete)

📄 app/Http/Controllers/Admin/UserController.php Controller
PHP 
<?php
// app/Http/Controllers/Admin/UserController.php
namespace App\Http\Controllers\Admin;

use App\Http\Controllers\Controller;
use App\Models\User;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Facades\Hash;
use Illuminate\Validation\Rule;

class UserController extends Controller
{
    // 1. Tampilkan Daftar Semua Pengguna (Admin & Customer)
    public function index(Request $request)
    {
        $query = User::query();

        // Filter Pencarian (Nama / Email)
        if ($request->filled('search')) {
            $search = $request->search;
            $query->where(function($q) use ($search) {
                $q->where('name', 'like', "%{$search}%")
                  ->orWhere('email', 'like', "%{$search}%")
                  ->orWhere('phone', 'like', "%{$search}%");
            });
        }

        // Filter Role (Admin / Customer)
        if ($request->filled('role')) {
            $query->where('role', $request->role);
        }

        $users = $query->latest()->paginate(10)->withQueryString();

        return view('admin.users.index', compact('users'));
    }

    // 2. Tampilkan Form Tambah Pengguna Baru
    public function create()
    {
        return view('admin.users.create');
    }

    // 3. Simpan Pengguna Baru ke Database
    public function store(Request $request)
    {
        $validated = $request->validate([
            'name'     => 'required|string|max:255',
            'email'    => 'required|email|max:255|unique:users,email',
            'phone'    => 'nullable|string|max:20',
            'role'     => 'required|in:admin,customer',
            'password' => 'required|string|min:6|confirmed',
        ]);

        $validated['password'] = Hash::make($validated['password']);

        User::create($validated);

        return redirect()->route('admin.users.index')->with('success', 'Pengguna baru berhasil ditambahkan!');
    }

    // 4. Form Edit Data Pengguna
    public function edit(User $user)
    {
        return view('admin.users.edit', compact('user'));
    }

    // 5. Perbarui Data Pengguna
    public function update(Request $request, User $user)
    {
        $validated = $request->validate([
            'name'     => 'required|string|max:255',
            'email'    => ['required', 'email', 'max:255', Rule::unique('users')->ignore($user->id)],
            'phone'    => 'nullable|string|max:20',
            'role'     => 'required|in:admin,customer',
            'password' => 'nullable|string|min:6|confirmed',
        ]);

        // Jika password diisi, enkripsi password baru; jika kosong jangan diubah
        if (!empty($validated['password'])) {
            $validated['password'] = Hash::make($validated['password']);
        } else {
            unset($validated['password']);
        }

        $user->update($validated);

        return redirect()->route('admin.users.index')->with('success', 'Data pengguna berhasil diperbarui!');
    }

    // 6. Hapus Data Pengguna (Dengan Proteksi Anti Self-Delete)
    public function destroy(User $user)
    {
        // PENTING: Mencegah admin menghapus akunnya sendiri yang sedang aktif
        if (Auth::id() === $user->id) {
            return back()->with('error', 'Tindakan ditolak! Anda tidak dapat menghapus akun Anda sendiri yang sedang aktif.');
        }

        $user->delete();

        return redirect()->route('admin.users.index')->with('success', 'Akun pengguna berhasil dihapus!');
    }
}

// app/Http/Controllers/Admin/OrderReportController.php
namespace App\Http\Controllers\Admin;

use App\Http\Controllers\Controller;
use App\Models\Order;
use App\Models\OrderDetail;
use Illuminate\Http\Request;

class OrderReportController extends Controller
{
    public function index(Request $request)
    {
        $query = Order::with(['user', 'orderDetails.ticket']);

        // 1. Filter Rentang Tanggal
        if ($request->filled('start_date') && $request->filled('end_date')) {
            $query->whereBetween('order_date', [$request->start_date, $request->end_date]);
        }

        // 2. Filter Status Pembayaran
        if ($request->filled('status')) {
            $query->where('status', $request->status);
        }

        // 3. Pencarian Kode Booking / Nama Customer
        if ($request->filled('search')) {
            $search = $request->search;
            $query->where(function($q) use ($search) {
                $q->where('order_code', 'like', "%{$search}%")
                  ->orWhere('customer_name', 'like', "%{$search}%");
            });
        }

        $orders = $query->latest()->paginate(10)->withQueryString();

        // 4. Ringkasan Statistik untuk Card Dashboard
        $totalOmset = Order::where('status', 'paid')->sum('total_price');
        $totalTicketsSold = OrderDetail::whereHas('order', function ($q) {
            $q->where('status', 'paid');
        })->sum('quantity');
        $totalPaidOrders = Order::where('status', 'paid')->count();
        $totalPendingOrders = Order::where('status', 'pending')->count();

        return view('admin.orders.index', compact(
            'orders',
            'totalOmset',
            'totalTicketsSold',
            'totalPaidOrders',
            'totalPendingOrders'
        ));
    }

    // 5. Update Status Pembayaran (Pending -> Paid / Cancelled)
    public function updateStatus(Request $request, $id)
    {
        $request->validate([
            'status' => 'required|in:pending,paid,cancelled'
        ]);

        $order = Order::findOrFail($id);
        $order->update(['status' => $request->status]);

        return back()->with('success', "Status pesanan {$order->order_code} berhasil diperbarui!");
    }

    // 6. Tampilan Cetak Laporan Resmi
    public function printReport(Request $request)
    {
        $query = Order::with(['user', 'orderDetails.ticket']);

        if ($request->filled('start_date') && $request->filled('end_date')) {
            $query->whereBetween('order_date', [$request->start_date, $request->end_date]);
        }
        if ($request->filled('status')) {
            $query->where('status', $request->status);
        }

        $orders = $query->latest()->get();

        return view('admin.orders.print', compact('orders'));
    }
}

DB::transaction & Pengurangan Stok

Customer dapat menjelajahi konser yang masih memiliki kuota stok > 0, memilih tiket, menjalankan checkout atomik dengan DB::transaction() dan decrement('stock'), serta mencetak e-tiket resmi dengan layout digital.

6.1 Controller BookingController (Customer Flow)

📄 app/Http/Controllers/Customer/BookingController.php Controller
PHP 
<?php
// app/Http/Controllers/Customer/BookingController.php
namespace App\Http\Controllers\Customer;

use App\Http\Controllers\Controller;
use App\Models\Order;
use App\Models\OrderDetail;
use App\Models\Ticket;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Facades\DB;

class BookingController extends Controller
{
    // 1. Katalog Konser Publik
    public function index()
    {
        $tickets = Ticket::where('stock', '>', 0)->latest()->get();
        return view('customer.concerts', compact('tickets'));
    }

    // 2. Form Booking Tiket
    public function showBookingForm($id)
    {
        $ticket = Ticket::findOrFail($id);
        return view('customer.booking-form', compact('ticket'));
    }

    // 3. Checkout Transaksi Atomik (DB::transaction & Pengurangan Stok)
    public function checkout(Request $request)
    {
        $request->validate([
            'ticket_id' => 'required|exists:tickets,id',
            'quantity'  => 'required|integer|min:1|max:5',
        ]);

        $ticket = Ticket::findOrFail($request->ticket_id);

        if ($ticket->stock < $request->quantity) {
            return back()->with('error', 'Maaf, kuota tiket tidak mencukupi sisa stok!');
        }

        // Jalankan Database Transaction untuk Menjamin Integritas Data
        DB::beginTransaction();
        try {
            $user = Auth::user();
            $subtotal = $ticket->price * $request->quantity;
            $orderCode = 'TKT-' . date('Ymd') . '-' . strtoupper(substr(uniqid(), -4));

            // Simpan Data Order Header
            $order = Order::create([
                'user_id'        => $user->id,
                'order_code'     => $orderCode,
                'customer_name'  => $user->name,
                'customer_email' => $user->email,
                'customer_phone' => $user->phone ?? '08123456789',
                'total_price'    => $subtotal,
                'status'         => 'paid', // Default lunas untuk simulasi ujian
                'order_date'     => now()->toDateString(),
            ]);

            // Simpan Detail Order
            OrderDetail::create([
                'order_id'   => $order->id,
                'ticket_id'  => $ticket->id,
                'quantity'   => $request->quantity,
                'unit_price' => $ticket->price,
                'subtotal'   => $subtotal,
            ]);

            // Kurangi Stok Tiket secara Atomik
            $ticket->decrement('stock', $request->quantity);

            DB::commit();

            return redirect()->route('customer.myTickets')->with('success', "Pemesanan berhasil! Kode Booking: {$orderCode}");
        } catch (\Exception $e) {
            DB::rollBack();
            return back()->with('error', 'Terjadi kesalahan transaksi: ' . $e->getMessage());
        }
    }

    // 4. Riwayat Tiket Saya
    public function myTickets()
    {
        $orders = Order::where('user_id', Auth::id())
            ->with('orderDetails.ticket')
            ->latest()
            ->get();

        return view('customer.my-tickets', compact('orders'));
    }

    // 5. Cetak E-Tiket Digital
    public function printTicket($id)
    {
        $order = Order::where('user_id', Auth::id())
            ->where('id', $id)
            ->with('orderDetails.ticket')
            ->firstOrFail();

        return view('customer.e-ticket', compact('order'));
    }
}

2. Fungsi ERD & Operasi CRUD dalam Bahasa SQL
Database Design & Manipulation

A. Fungsi ERD (Entity Relationship Diagram)

ERD adalah diagram pemodelan visual yang mendeskripsikan struktur basis data, entitas, atribut, dan relasi logis antar-tabel sebelum diterapkan ke dalam database fisik. Fungsi utamanya meliputi:

  1. Cetak Biru (Blueprint) Perancangan: Panduan visual utama bagi developer untuk menyusun migration file dan model Eloquent secara terstruktur.
  2. Mendefinisikan Entitas & Atribut: Menetapkan tabel apa saja yang ada (users, tickets, orders, order_details) beserta tipe data dan Primary Key (PK).
  3. Menetapkan Kardinalitas Relasi: Menentukan keterkaitan 1:N (Satu User memiliki banyak Orders, Satu Order memiliki banyak OrderDetails) dan N:M (Orders ke Tickets melalui tabel pivot OrderDetails).
  4. Menjaga Integritas Referensial: Menentukan aturan Foreign Key seperti ON DELETE CASCADE agar tidak timbul data yatim (orphan records).
  5. Mencegah Redundansi Data: Membantu normalisasi database (1NF, 2NF, 3NF) agar data tidak terduplikasi.

B. Fungsi CRUD dalam Bahasa SQL & Contoh Nyata Kasus Tiket Konser

CRUD adalah singkatan dari 4 operasi inti manipulasi data pada basis data relasional:

Huruf Operasi Perintah SQL Fungsi Utama & Penjelasan
C Create INSERT INTO ... VALUES Menambahkan baris rekaman baru ke dalam tabel basis data.
R Read SELECT ... FROM ... WHERE Membaca, mengambil, menyaring, dan menampilkan data rekaman tabel.
U Update UPDATE ... SET ... WHERE Memperbarui atau mengubah nilai data yang telah ada pada baris tabel tertentu.
D Delete DELETE FROM ... WHERE Menghapus baris rekaman data dari tabel basis data.

3. Apa Itu Query, Fungsi SQL, dan Contoh Nyata
SQL Queries & Functions

A. Pengertian Query

Query adalah instruksi atau perintah terstruktur dalam bahasa SQL yang dikirimkan oleh aplikasi ke Relational Database Management System (RDBMS) untuk meminta data, memfilter kondisi tertentu, melakukan perhitungan matematika, mengupdate rekaman, atau memanipulasi struktur tabel.

B. Fungsi & Manfaat Query

  • Penyaringan Data Presisi (WHERE, LIKE): Mengambil data secara spesifik tanpa membuang memori server.
  • Penggabungan Relasi Multi-Tabel (JOIN): Menyajikan data terpadu dari beberapa tabel yang terpisah (misal: menyajikan nama customer dari tabel orders bersama judul konser dari tabel tickets).
  • Kalkulasi & Agregasi Statistik Cepat (SUM, COUNT, AVG): Menghitung omset kotor, total tiket terjual, dan jumlah order langsung di level mesin database secara instan.
  • Pengelompokan Analisis (GROUP BY): Mengelompokkan transaksi untuk mengetahui kategori tiket mana yang paling laris.
  • Efisiensi Bandwidth: Menghindari penarikan data yang tidak perlu (SELECT id, concert_name vs SELECT *).

C. Contoh Query Relasional & Agregasi Kasus Tiket Konser

📄 Query SQL Relasional & Agregasi SQL Query
SQL 
-- Contoh 1: Query Agregasi Total Omset Pendapatan Lunas (Statistik Dashboard)
SELECT 
    COUNT(id) AS total_transaksi,
    SUM(total_price) AS total_omset_rupiah,
    AVG(total_price) AS rata_rata_per_pesanan
FROM orders 
WHERE status = 'paid';

-- Contoh 2: Relasi Multi-Tabel (INNER JOIN) Rekap Rincian Pesanan
SELECT 
    o.order_code,
    o.customer_name,
    o.customer_phone,
    t.concert_name,
    t.category,
    od.quantity,
    od.unit_price,
    od.subtotal,

    o.order_date

INNER JOIN tickets t ON od.ticket_id = t.id

HAVING total_pendapatan > 5000000;

4. Arsitektur MVC Laravel (Model - View - Controller)
Software Architecture

A. Definisi Konsep Tiga Komponen MVC

  • Model (M): Bertanggung jawab mengelola data dan struktur tabel, berkomunikasi langsung dengan database MySQL melalui Eloquent ORM, dan mendefinisikan relasi antar-tabel (terletak di app/Models/, contoh: Ticket.php, User.php, Order.php).
  • View (V): Bertanggung jawab menyajikan antarmuka grafis kepada pengguna (UI/UX) menggunakan Blade template engine yang modular (terletak di resources/views/, contoh: customer/concerts.blade.php, admin/orders/index.blade.php).
  • Controller (C): Bertindak sebagai otak atau jembatan penghubung (traffic controller). Menerima HTTP Request dari rute (route), memanggil Model untuk mengambil atau menyimpan data, menerapkan logika bisnis (misal validasi input atau transaksi atomik kuota tiket), lalu mengoper data ke View untuk dirender ke browser (terletak di app/Http/Controllers/).
  • Routing (routes/web.php): Pintu gerbang utama yang memetakan URL dan method HTTP (GET, POST, PUT, DELETE, PATCH) ke Controller yang sesuai.

B. Diagram Alur Kerja Request-Response Lifecycle di Laravel

1
Client Browser Mengirim Request

Pengguna mengklik tombol "Beli Tiket" (mengirimkan HTTP POST ke /checkout).

2
Routing (routes/web.php)

Route mencocokkan URL dan mengarahkan request ke BookingController@checkout.

3
Middleware Filter

Middleware auth dan VerifyCsrfToken memeriksa apakah pengguna sudah login dan token CSRF valid.

4
Controller Logic & Model Execution

Controller memvalidasi input, lalu memanggil Model Ticket dan Order untuk menyimpan data dan mengurangi kuota tiket.

5
Database Execution & Commit

Mesin MySQL mengeksekusi perintah SQL secara atomik (ACID) dan menyimpan record ke disk storage.

6
View Rendering & HTTP Response

Controller merender file Blade View dengan flash message sukses, dan mengembalikannya ke browser sebagai HTML utuh.

C. Keuntungan Menggunakan Pola MVC di Laravel

  1. Separation of Concerns: Pemisahan tugas yang jelas sehingga kode program rapi, mudah dibaca, dan tidak campur aduk (kode HTML terpisah dari baris SQL).
  2. Kemudahan Pemeliharaan (Maintainability): Jika ada revisi desain UI, developer cukup mengubah file Blade tanpa takut merusak logika transaksi di Controller.
  3. Reusability Kode: Satu Model dapat digunakan oleh banyak Controller yang berbeda secara efisien.
  4. Standar Penilaian Sertifikasi BNSP: Menunjukkan kompetensi pemrograman web berorientasi objek yang terstruktur dan profesional.

{
    public function index()
    {
        $foods = Food::latest()->paginate(10);
        return view('foods.index', compact('foods'));
    }

    public function store(Request $request)
    {
        $validated = $request->validate([
            'name'        => 'required|string|max:255',
            'category'    => 'required|in:Makanan,Minuman,Cemilan',
            'price'       => 'required|numeric|min:0',
            'description' => 'required|string',
            'image'       => 'nullable|image|mimes:jpeg,png,jpg|max:2048',
        ]);

        if ($request->hasFile('image')) {
            $validated['image'] = $request->file('image')->store('foods', 'public');
        }

        Food::create($validated);
        return redirect()->route('foods.index')->with('success', 'Menu berhasil ditambahkan!');
    }
}

10 Pertanyaan Jebakan Asesor & Jawaban Ilmiah

Hafalkan konsep dan kata kunci dari 10 pertanyaan teknis berikut. Asesor menguji kedalaman pemahaman Anda terhadap arsitektur sistem, keamanan data, dan integritas basis data.

❓ Pertanyaan 1: "Mengapa Anda memisahkan tabel orders dan order_details, bukan langsung menyimpan tiket di tabel orders?"
🗣️ Jawaban Rekomendasi: Karena hubungan antara pesanan dan tiket adalah One-to-Many (1 pemesan bisa membeli beberapa tiket sekaligus). Memisahkan tabel ke dalam order_details menerapkan kaidah Normalisasi Basis Data (3NF), mencegah redundansi data, dan memungkinkan pencatatan harga satuan historis saat transaksi terjadi.
❓ Pertanyaan 2: "Bagaimana sistem Anda mencegah race condition ketika tiket tersisa 1 namun dibeli oleh dua customer bersamaan?"
🗣️ Jawaban Rekomendasi: Saya membungkus alur checkout menggunakan Database Transaction (DB::beginTransaction() dan DB::commit()) serta validasi pengecekan stok di level backend server. Pada aplikasi enterprise skala besar, kita dapat menerapkan Pessimistic Locking dengan menambahkan lockForUpdate() pada query tiket.
❓ Pertanyaan 3: "Apa fungsi perintah php artisan storage:link?"
🗣️ Jawaban Rekomendasi: Membuat tautan pintasan (symbolic link) dari direktori privat storage/app/public ke direktori publik public/storage, sehingga file upload (seperti banner poster konser) dapat diakses dan ditampilkan dengan aman oleh browser melalui URL publik.
❓ Pertanyaan 4: "Apa itu Mass Assignment Vulnerability dan bagaimana Laravel melindunginya?"
🗣️ Jawaban Rekomendasi: Kerentanan keamanan di mana penyerang menyisipkan field berbahaya ke dalam formulir HTTP (seperti menyusupkan input role=admin saat registrasi). Laravel memproteksinya dengan mewajibkan array properti $fillable pada Model, sehingga hanya kolom yang didefinisikan secara eksplisit yang diizinkan diisi secara massal.
❓ Pertanyaan 5: "Jelaskan fungsi sintaks @csrf pada setiap formulir Blade!"
🗣️ Jawaban Rekomendasi: Menghasilkan token rahasia satu kali pakai (*anti-forgery token*) yang divalidasi oleh VerifyCsrfToken Middleware untuk melindungi aplikasi dari serangan Cross-Site Request Forgery (CSRF).
❓ Pertanyaan 6: "Apa perbedaan query Eloquent menggunakan with() dibanding tanpa with()?"
🗣️ Jawaban Rekomendasi: with() menerapkan teknik Eager Loading yang menggabungkan query relasi di awal, sehingga menghindari masalah N+1 Query Problem yang dapat memperlambat kinerja server secara signifikan.
❓ Pertanyaan 7: "Kapan kita menggunakan relasi belongsTo dan kapan hasMany?"
🗣️ Jawaban Rekomendasi: belongsTo diletakkan pada model tabel anak yang memegang kolom Foreign Key (seperti OrderDetail yang memegang order_id dan ticket_id). Sedangkan hasMany diletakkan pada model tabel induk yang memiliki banyak relasi (seperti Order yang memiliki banyak OrderDetail).
❓ Pertanyaan 8: "Mengapa harga tiket disimpan ulang di kolom unit_price pada order_details padahal sudah ada di tabel tickets?"
🗣️ Jawaban Rekomendasi: Untuk menjaga integritas data historis keuangan. Jika suatu saat panitia menaikkan harga tiket master dari 500 ribu menjadi 700 ribu, total omset pesanan masa lalu tidak akan ikut berubah secara keliru.
❓ Pertanyaan 9: "Bagaimana cara Anda membatasi agar customer biasa tidak bisa mengakses URL /admin/dashboard?"
🗣️ Jawaban Rekomendasi: Menggunakan Middleware otorisasi khusus (IsAdmin) yang memeriksa apakah Auth::user()->role === 'admin'. Jika bukan admin, pengguna otomatis ditolak dan diarahkan kembali.
❓ Pertanyaan 10: "Sebutkan tahapan siklus hidup request dari browser sampai tampilan konser muncul!"
🗣️ Jawaban Rekomendasi: Client HTTP Request -> routes/web.php -> Middleware (Auth/CSRF) -> Controller -> Model Eloquent -> Database MySQL (InnoDB) -> Controller mengolah data -> Blade View Render HTML -> Browser Client menampilkan halaman.
