📌 KAMUS WAJIB: KAPAN MEMAKAI Food, food, ATAU foods

⚠️ Mengapa Masalah 'Food vs foods' Sering Memicu Error?

Kata 'food' dalam bahasa Inggris adalah uncountable noun (kata benda tak terhitung). Secara default, generator Laravel terkadang menganggap jamak dari 'food' tetap 'food', sehingga saat Anda menjalankan php artisan make:model Food -m, Laravel bisa menghasilkan migrasi create_food_table (tunggal). Hal ini memicu error fatal foreign key pada order_details atau error Table 'pesanmakan.foods' doesn't exist saat Eloquent dijalankan.

4 Formula Emas Penamaan Laravel:

  • Nama Tabel MySQL: Wajib jamak foods (berakhiran s) di migrasi: Schema::create('foods', ...).
  • Model Eloquent: Wajib tegaskan protected $table = 'foods'; di app/Models/Food.php.
  • Kolom Foreign Key: Tuliskan relasi secara eksplisit: $table->foreignId('food_id')->constrained('foods')->cascadeOnDelete(); di tabel order_details.
  • Variabel Controller: Gunakan tunggal $food untuk 1 record menu dan jamak $foods untuk collection menu.
Objek Penulisan Contoh di Kode Penjelasan
Model (PHP Class) Food (Kapital, Tunggal) class Food extends Model
Food::all()		 Representasi 1 entitas objek model Eloquent.
Tabel MySQL foods (Kecil, Jamak) Schema::create('foods', ...)
protected $table = 'foods';		 Nama fisik tabel database di MySQL (wajib berakhiran 's').
Kolom Foreign Key food_id (Kecil, Tunggal + _id) $table->foreignId('food_id')->constrained('foods') Kolom relasi kunci asing di tabel order_details.
Variabel Tunggal $food (Kecil, Tunggal) public function edit(Food $food)
$food = Food::findOrFail($id);		 Menyimpan 1 objek record menu makanan.
Variabel Jamak $foods (Kecil, Jamak) $foods = Food::latest()->paginate(10); Menyimpan kumpulan (collection) banyak menu makanan.

{
    Schema::create('order_details', function (Blueprint $table) {
        $table->id();

- foreignId('food_id')->constrained('foods'): Mengunci integritas ke tabel master 'foods'.
- cascadeOnDelete(): Jika data order dihapus, semua baris rincian di tabel order_details otomatis ikut terhapus bersih.

namespace App\Http\Controllers;

use App\Models\Food;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Storage; // <-- [TAMBAHKAN] Wajib untuk kelola file storage

class FoodController extends Controller
{
    // 1. Tampilkan tabel daftar makanan (index)
    public function index()
    {
        $foods = Food::latest()->paginate(10);
        return view('admin.foods.index', compact('foods'));
    }

    // 2. Tampilkan form tambah makanan baru (create)
    public function create()
    {
        return view('admin.foods.create');
    }

    // 3. Simpan data makanan baru + upload gambar (store)
    public function store(Request $request)
    {
        $request->validate([
            'name'        => 'required|string|max:255',
            'category'    => 'required|in:Makanan,Minuman,Cemilan',
            'price'       => 'required|numeric|min:0',
            'description' => 'required|string',
            'image'       => 'nullable|image|mimes:jpeg,png,jpg|max:2048',
        ]);

        $imagePath = null;
        if ($request->hasFile('image')) {
            $imagePath = $request->file('image')->store('foods', 'public');
        }

        Food::create([
            'name'        => $request->name,
            'category'    => $request->category,
            'price'       => $request->price,
            'description' => $request->description,
            'image'       => $imagePath,
        ]);

        return redirect()->route('foods.index')
            ->with('success', 'Makanan berhasil ditambahkan!');
    }

    // 4. Detail makanan (show -> redirect saja ke edit)
    public function show(Food $food)
    {
        return view('admin.foods.edit', compact('food'));
    }

    // 5. Tampilkan form edit makanan (edit)
    public function edit(Food $food)
    {
        return view('admin.foods.edit', compact('food'));
    }

    // 6. Update data makanan + ganti gambar lama (update)
    public function update(Request $request, Food $food)
    {
        $request->validate([
            'name'        => 'required|string|max:255',
            'category'    => 'required|in:Makanan,Minuman,Cemilan',
            'price'       => 'required|numeric|min:0',
            'description' => 'required|string',
            'image'       => 'nullable|image|mimes:jpeg,png,jpg|max:2048',
        ]);

        $imagePath = $food->image;
        if ($request->hasFile('image')) {
            // Hapus gambar lama jika ada di storage fisik
            if ($food->image && Storage::disk('public')->exists($food->image)) {
                Storage::disk('public')->delete($food->image);
            }
            // Simpan gambar baru
            $imagePath = $request->file('image')->store('foods', 'public');
        }

        $food->update([
            'name'        => $request->name,
            'category'    => $request->category,
            'price'       => $request->price,
            'description' => $request->description,
            'image'       => $imagePath,
        ]);

        return redirect()->route('foods.index')
            ->with('success', 'Makanan berhasil diperbarui!');
    }

    // 7. Hapus data makanan + hapus gambar fisik (destroy)
    public function destroy(Food $food)
    {
        if ($food->image && Storage::disk('public')->exists($food->image)) {
            Storage::disk('public')->delete($food->image);
        }
        $food->delete();

        return redirect()->route('foods.index')
            ->with('success', 'Makanan berhasil dihapus!');
    }
}

<?php

namespace App\Http\Controllers;

use App\Models\Food;               // <-- [TAMBAHKAN] Model Menu
use App\Models\Order;              // <-- [TAMBAHKAN] Model Order Header
use App\Models\OrderDetail;        // <-- [TAMBAHKAN] Model Detail Order
use Illuminate\Http\Request;
use Illuminate\Support\Facades\DB; // <-- [TAMBAHKAN] Wajib untuk DB::transaction

class OrderController extends Controller
{
    // 1. Tampilkan katalog menu publik untuk customer
    public function index()
    {
        $foods = Food::all();
        return view('customer.index', compact('foods'));
    }

    // 2. Simpan transaksi pesanan (multi-tabel aman dengan DB::transaction)
    public function store(Request $request)
    {
        $request->validate([
            'customer_name' => 'required|string|max:255',
            'table_number'  => 'required|integer|min:1',
            'items'         => 'required|array',
            'items.*'       => 'nullable|integer|min:0',
        ]);

        // Filter: Hanya ambil menu yang jumlah porsinya > 0
        $orderedItems = array_filter($request->items, fn($qty) => (int)$qty > 0);

        if (empty($orderedItems)) {
            return back()->with('error', 'Pilih minimal satu menu dengan jumlah porsi lebih dari 0!');
        }

        DB::beginTransaction();
        try {
            // A. Simpan data header pesanan ke tabel 'orders'
            $order = Order::create([
                'customer_name' => $request->customer_name,
                'table_number'  => $request->table_number,
                'total_price'   => 0, // Akan dihitung dan diupdate setelah rincian dihitung
                'status'        => 'Pending',
            ]);

            $totalPrice = 0;

            // B. Looping simpan rincian per menu ke tabel 'order_details'
            foreach ($orderedItems as $foodId => $quantity) {
                $food = Food::findOrFail($foodId);
                $subtotal = $food->price * $quantity;
                $totalPrice += $subtotal;

                OrderDetail::create([
                    'order_id' => $order->id,
                    'food_id'  => $food->id,
                    'quantity' => $quantity,
                    'subtotal' => $subtotal,
                ]);
            }

            // C. Perbarui total harga akhir di tabel header 'orders'
            $order->update(['total_price' => $totalPrice]);

            DB::commit(); // Transaksi berhasil, kunci data permanen ke MySQL

            return redirect()->route('customer.index')
                ->with('success', "Pesanan Meja {$order->table_number} atas nama {$order->customer_name} berhasil! Total: Rp " . number_format($totalPrice));

        } catch (\Exception $e) {
            DB::rollBack(); // Terjadi error, batalkan semua insert data!
            return back()->with('error', 'Gagal memproses pesanan: ' . $e->getMessage());
        }
    }
}

- array_filter($request->items, fn($qty) => (int)$qty > 0): Menyaring item yang porsinya 0 sehingga database tidak menyimpan baris kosong.
- DB::beginTransaction() & DB::rollBack(): PRINSIP ACID DATABASE! Menjamin konsistensi: jika insert ke order_details gagal, pembuatan header di orders otomatis dibatalkan. Tidak ada 'data hantu' di database.
- $food->price * $quantity: Harga selalu dihitung dari tabel master foods di server, BUKAN dari kiriman input form, sehingga mencegah manipulasi harga oleh hacker.

🔥 SESI GRILL-ME: 10 PERTANYAAN WAWANCARA ASESOR BNSP BESERTA JAWABAN JITU

Asesor Sertifikasi Kompetensi (BNSP/LSP) selalu melakukan tes wawancara lisan (oral assessment) untuk memastikan Anda benar-benar paham logika di balik kode yang Anda tulis. Pelajari 10 jawaban jitu di bawah ini:

❓ Pertanyaan 1: Mengapa Anda menggunakan DB::beginTransaction() dan DB::rollBack() pada proses checkout pesanan?
Jawaban Jitu: Untuk menjamin prinsip ACID (khususnya Atomicity). Karena checkout melibatkan penyimpanan ke dua tabel yang saling bergantung ('orders' dan 'order_details'), jika penyimpanan rincian menu gagal di tengah jalan (misal server error atau foreign key gagal), DB::rollBack() akan membatalkan seluruh perubahan. Ini mencegah timbulnya 'data hantu' (header order tersimpan tanpa ada detail rincian menu) dan memastikan integritas data keuangan tetap akurat.
❓ Pertanyaan 2: Apa fungsi perintah 'php artisan storage:link' dan apa dampaknya jika lupa dijalankan?
Jawaban Jitu: Secara default, Laravel menyimpan file upload di folder internal 'storage/app/public/' yang tidak bisa diakses langsung oleh browser demi alasan keamanan. Perintah 'storage:link' membuat symbolic link (shortcut) dari folder 'public/storage' ke 'storage/app/public/'. Jika lupa dijalankan, seluruh gambar yang diupload tidak akan tampil di browser (menghasilkan error HTTP 404 / gambar rusak).
❓ Pertanyaan 3: Mengapa Anda menggunakan 'protected $guarded = ['id'];' daripada '$fillable' pada Model Eloquent?
Jawaban Jitu: Ini adalah strategi efisiensi dan kecepatan saat ujian Serkom. '$fillable' bersifat whitelist di mana kita harus mendaftarkan setiap kolom satu per satu. Dengan '$guarded = ['id'];' (blacklist), kita melindungi kolom 'id' agar tidak dimanipulasi, sementara seluruh kolom lainnya otomatis diizinkan untuk mass-assignment (Food::create). Ini menghemat waktu pengetikan dan mencegah error MassAssignmentException jika ada penambahan kolom.
❓ Pertanyaan 4: Mengapa pada form edit Anda menggunakan direktif Blade @method('PUT'), padahal form HTML hanya mendukung GET dan POST?
Jawaban Jitu: Browser web secara native hanya mendukung method HTTP GET dan POST. Untuk mengikuti standar arsitektur RESTful API di mana operasi pembaruan data menggunakan method PUT atau PATCH, Laravel menyediakan fitur Method Spoofing. Direktif @method('PUT') menyisipkan tag tersembunyi <input type='hidden' name='_method' value='PUT'> sehingga router Laravel dapat mengenali request tersebut sebagai PUT.
❓ Pertanyaan 5: Apa fungsi direktif @csrf dan apa yang terjadi jika form tidak diberi @csrf?
Jawaban Jitu: @csrf menyisipkan token rahasia Cross-Site Request Forgery untuk memastikan bahwa request submit form benar-benar berasal dari aplikasi kita, bukan dari eksploitasi skrip pihak ketiga. Jika tidak dipasang, Laravel Middleware (VerifyCsrfToken) akan menolak kiriman form dengan melempar error '419 Page Expired'.
❓ Pertanyaan 6: Jelaskan relasi Eloquent antara model Food, Order, dan OrderDetail!
Jawaban Jitu: Relasi antara Order dan OrderDetail adalah One-to-Many: 1 transaksi Order memiliki banyak OrderDetail ($order->hasMany(OrderDetail::class)). Sebaliknya, OrderDetail memiliki relasi Many-to-One balik ke Order ($detail->belongsTo(Order::class)) dan Many-to-One ke Food ($detail->belongsTo(Food::class)). Dengan relasi ini, kita dapat memanggil nama menu yang dipesan di dashboard admin dengan sintaks elegan: $detail->food->name.
❓ Pertanyaan 7: Mengapa urutan pembuatan tabel pada migration harus: foods -> orders -> order_details?
Jawaban Jitu: Karena tabel 'order_details' memiliki dua foreign key ('order_id' yang merujuk ke tabel 'orders' dan 'food_id' yang merujuk ke tabel 'foods'). Di database relasional, tabel induk HARUS dibuat terlebih dahulu sebelum tabel anak. Jika tabel 'order_details' dijalankan lebih awal, MySQL akan menolak dengan error 'Foreign key constraint fails' karena tabel tujuan belum ada.
❓ Pertanyaan 8: Apa keuntungan menggunakan Eager Loading Order::with('orderDetails.food') di dashboard admin?
Jawaban Jitu: Untuk mencegah masalah 'N+1 Query Problem'. Jika kita hanya memanggil Order::all() (Lazy Loading), setiap kali loop menampilkan rincian dan nama makanan, Laravel akan mengeksekusi query database baru secara berulang-ulang. Dengan Eager Loading with('orderDetails.food'), Laravel hanya menjalankan 3 query teroptimasi di awal, sehingga loading dashboard jauh lebih cepat dan hemat memori server.
❓ Pertanyaan 9: Mengapa tag form tambah dan edit makanan wajib memiliki atribut enctype='multipart/form-data'?
Jawaban Jitu: Secara default, form HTML mengirimkan data dengan encoding teks 'application/x-www-form-urlencoded'. Atribut 'enctype="multipart/form-data"' memerintahkan browser untuk memecah data form menjadi bagian biner sehingga file fisik gambar dapat ditransmisikan ke server. Tanpa atribut ini, method $request->file('image') di controller akan selalu bernilai null.
❓ Pertanyaan 10: Bagaimana Anda memastikan tidak ada file foto sampah yang menumpuk di server saat makanan diedit atau dihapus?
Jawaban Jitu: Di FoodController pada method update() dan destroy(), kita melakukan pengecekan keberadaan foto lama dengan 'Storage::disk('public')->exists($food->image)'. Jika ada, kita menghapus file fisik tersebut dengan 'Storage::disk('public')->delete($food->image)' sebelum mengunggah foto baru atau sebelum record model dihapus.
